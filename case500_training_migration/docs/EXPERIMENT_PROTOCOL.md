# case500 与 case118 统一的端点训练协议

本包以 liuy 服务器正在运行的 `endpoint_training_v2` 为训练来源。源文件已与实际 case118 `45k/seed44` 保存的代码 SHA256 对照，模型、损失及训练/评测源文件匹配。来源和版本见根目录 `SOURCE_PROVENANCE.json`。

## 1. 正式实验设置

| 项目 | 固定设置 |
|---|---|
| 任务 | 固定运行输入，指定线路 `ρ=0,1` 的普通 AC-PF 端点预测 |
| 模型 | CANOS-PF，hidden_dim=128，20 层消息传递，include_sent_messages=True |
| 模型种子 | 11、22、33、44、55；每个训练规模使用相同父工况集合 |
| 优化器 | Adam，lr=0.0005，weight_decay=0 |
| 学习率 | 前 5 epochs 用 LinearLR，factor 从 0.01 到 1；之后 StepLR 每 4 epochs 乘 0.9 |
| 训练 | 300 epochs，batch_size=64，shuffle=True，drop_last=False |
| 验证 | 固定集合，batch_size=50，每 2 epochs 一次，末轮也验证 |
| 模型选择 | 完整验证集 MSE 最小的 checkpoint，随后在完整固定测试集评测 |
| 数值与加载 | FP32，不启用 AMP/TF32；num_workers=0，pin_memory=False，torch_threads=4 |
| 数据归一化 | 沿用服务器：不新增输入/标签标准化，transform/pre_transform 均为 None |
| 恢复 | 保存模型、优化器、scheduler 和随机状态；从最后完整 epoch 恢复 |
| GPU 调度 | 默认每张指定 GPU 同时 3 个独立任务；不是单模型分布式训练 |

训练损失是 `MSE_PQ + MSE_PV + MSE_Slack + MSE_Branch`：先在各部分内平均，再把四部分相加，**不是再除以 4**。分量包括角度、电压、功率等原有输出量；沿用原计算口径。PBL 是测试时报告的节点功率不平衡指标，当前没有额外加入训练损失。

`PBL Mean` 是先对每张图各节点的 `sqrt(ΔP²+ΔQ²)` 取平均，再对图取平均。另保存分项 MSE、按 rho 和线路的统计及逐样本结果。不要将 `PBL Max`、`PBL L2` 或相对 PBL 当作 `PBL Mean`。

CUDA scatter 等运算可能存在数值非确定性；固定种子和版本不承诺不同硬件上逐位相同。

## 2. 数据量和划分

训练规模为 `10k,20k,40k,45k,50k,55k,60k,80k,90k,100k,110k,120k,160k,320k`，单位是**端点图记录**。一个父工况包含指定线路和固定运行输入，并对应两条端点记录，所以 40k = 20,000 个父工况，320k = 160,000 个父工况。

默认完整实验是 14 个规模 × 5 个种子 = 70 次训练。可先配置少数规模，其余规模的数据成员关系保持冻结。

使用此前 `case500_migration` 生成包已冻结的划分：

- 502 条可断普通线路；此数不同于包含可断变压器的 582 条。
- 最大训练集 320,000 条端点记录。
- 验证集每条线路 50 个父工况，共 25,100 个父工况 / 50,200 条记录。
- 测试集同样为 25,100 个父工况 / 50,200 条记录。
- 所有规模共用同一验证和测试集，不随训练量扩大。
- 每个训练规模的线路配额尽可能均衡，按生成包中的输入特征分层方案取嵌套子集。

缓存转换按源 `plan.json` 和冻结索引核验数量，不把 502 或 50,200 写死成所有电网通用常量。`--scales` 只控制本次构建哪些缓存，不重新抽取数据。

同一父工况的两个端点必须在同一集合；父工况 ID 和精确已知输入指纹不可跨训练、验证和测试重合。近似模式可以在三套集合出现。这改善 ID 评测的可比性，不证明小训练集已经覆盖所有联合模式。

本训练包不依据模型误差删样本，也不自行添加电压窗口或改变已冻结的划分。标签是否满足设备运行限额，与能否满足普通 PF 方程是不同问题；这里继承生成包的接受规则。

## 3. 与中间样本研究的关系

当前交付先跑端点基线，训练器会拒绝混入 `ρ=0.5` 的数据。它没有把 rho 插值或光滑性正则自动加入损失。

后续可固定 40k 端点的 20,000 个父工况，生成对应中间标签，比较 `40k+5k/10k/15k/20k` 与纯端点 `45k/50k/55k/60k`；80k 系列对应 `90k/100k/110k/120k`。中间样本只能来自训练父工况，并复用相同验证、测试及模型种子。这些是后续配对实验的设计，当前包没有声称已生成或训练这些增强数据。

端点普通 PF 标签采用生成包显式指定的 Newton 协议；训练阶段直接读取标签，不再求解 PF，不把 ACOPF 源解改写为端点标签。Newton 收敛不构成同一解分支或动态稳定性的严格证明。

## 4. 跨电网比较的解释

case500 保持与 case118 相同的模型和训练规则，但网络规模、工况和输出数值分布不同。先比较各 case 内的数据规模曲线、五种子的离散程度，以及相同总记录数下中间样本的相对作用；不要仅凭两个电网的绝对 MSE 判定泛化强弱。

固定 epochs 和 batch size 时，大训练集拥有更多梯度更新；这是当前样本规模实验协议，不是固定计算预算实验。调整 case500 的 batch、轮数或精度应在正式实验开始前明确记录，避免把这些变化混入原有规模曲线。

每卡 3 个任务是默认队列设置，不代表所有 GPU 都能容纳 case500 的三份训练。先在目标卡做单任务小试，再确认三任务并发。若显存不足，可以减少并发任务数；这不改变单个模型的 batch、优化器或训练轮数。
